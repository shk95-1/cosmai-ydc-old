## 2. 다른 파트가 바로 쓸 수 있는 것

### ① 근거 검색 — LLM 도구로 붙일 수 있습니다

```bash
python bm25.py --query "판테놀 쓰는 선크림" --per-source --top 2
```

한 질의가 **네 소스에서 각각** 근거를 가져옵니다.

```
[youtube_comment]  판테놀 무기자차 선크림 진리임..ᅲ
[youtube_video]    무너진 피부장벽 판테놀을 써야하는 이유
[formula_full]     제로이드 데일리 선크림 — 전성분 26.판테놀, 27.펜틸렌글라이콜
[mfds]             앤서나인틴시카판테놀데일리선크림 · 바이오톡스 · 2019-04-15 · SPF50+ PA++++
[ingredient]       판테놀 — 209개 제품 36.2% · 평균 배합순위 28위로 미량 배합
[formula_summary]  듀이트리 어반쉐이드 더마 판테놀5 — 무기자차 · 전성분 36종
```

**전역 상위 k 를 쓰면 안 됩니다.** 색인의 92%가 짧은 유튜브 댓글(24만 개, 평균
16토큰)이라 BM25 길이 보정이 그쪽을 독점합니다. `mfds` 는 전역 293위, `ingredient`
는 300위 밖이었습니다. **소스별로 나눠 물어야** 근거가 모입니다.

각 결과에 `doc_id` · 소스 · 원본 링크가 붙습니다. LLM 이 숫자를 답할 때 **그 숫자의
원문 근거**를 대는 자리입니다.

### ② 청크 계약 검증기

```bash
python chunks.py --validate 받은파일.csv
```

계약 5칸(`chunk_id · doc_id · source · ordinal · text`) 위반 11종을 잡습니다.
인코딩 전에 걸러야 합니다 — 28만 청크를 GPU 로 태운 다음 `doc_id` 가 어긋난 걸
알면 처음부터 다시입니다.

수호님 청크에서 실제로 두 종류를 잡았습니다(정규화 누락 215행 · `doc_id` 충돌
2,120행). 후처리는 `repair_chunks.py` 로 막아 뒀고, 생성기 쪽 수정은 따로 부탁했습니다.

### ③ 성분 사전 (수호님 것 정제)

`seeds/ingredient_dictionary.tsv` — 1,877행. 각주(`*`)와 안내문이 붙은 21항목을
걸렀습니다.

**효과를 측정했습니다.** 성분명 1,877종 중 한 토큰으로 나오는 것이
**765(41%) → 1,873(100%)** 입니다.

```
사전 없이:  1,2-헥산다이올 → ['1', ',', '2', '-', '헥산다이올']
```

**성분명 절반 이상이 검색 불가였습니다.** 성분을 다루는 어느 코드든 이 사전이 필요합니다.

## 3. 저희가 확인한 것 (숫자 쓰실 때 참고)

| 발견 | 값 |
|---|---|

| 신고 필드(`has_paid_product_placement`)만 보면 | 254편 — **절반을 놓칩니다** |
| 광고를 빼면 판정 | **64셀 중 19셀 뒤집힘** |
| 혼합자차 — 제품 vs 담론 | 제품 32.9% vs 댓글 1.21% (**27.1배**) |

| 나이아신아마이드 배합 순위 | 375제품(69.4%) · **중앙 9위** |

입니다. 아데노신은 **한 번도 고함량으로 안 쓰입니다.** MASTER_REPORT §5-② 의
"미백만 고함량 배치" 발견이 청크 텍스트에서 그대로 재현됩니다.

## 4. 저희가 못 하는 것 (발표 방어선)

**① 예측이 안 됩니다.** 후향 검증 11건 결과입니다.

| 기준 | 적중 | 기저율 |
|---|---:|---:|
| A 판정 후에도 계속 올랐나 | **27%** | 47% |
| B 올라간 수준이 유지됐나 | **64%** | 47% |
| A (상승 계열 9건만) | **22%** | 47% |

13분기 · 계절 상품 · 964편으로는 예측 모델을 세울 수 없습니다. 그래서 카드는
"뜰 것이다"가 아니라 **"지금 이런 비대칭이 있다"** 로 씁니다.

> 팀의 ML 파트도 독립적으로 같은 곳에 도달했습니다 — 모델 A 가 baseline 상대로
> 9판 6승 3패, 모델 E(논문 수 → 매출)는 넣으니 오히려 나빠졌습니다.

**② 제품 단위 조인이 안 됩니다.** 팀에서 **세 사람이 독립적으로 같은 벽**에 부딪혔습니다.

```
팀원 매처          100개 중 38개
MASTER_REPORT     정확일치 119/577 (20.6%), 퍼지매칭은 오매칭으로 폐기
우리              시도하지 않음
```

원인도 같습니다 — 올리브영 상품의 상당수가 `기획/N종 택1` **묶음 페이지**입니다.
제품이 아니라 진열대입니다.

**③ 사전에 없는 성분은 관측되지 않습니다.** 그 한계를 숫자로 재서 11종을 찾았고,
**자동으로 사전에 넣지 않았습니다** — 넣으면 임계값·판정·카드가 전부 다시 계산되고
팀에 공유한 숫자와 어긋납니다.

## 5. 같은 함정을 세 번 밟았습니다

| 언제 | 무엇이 관측값이 됐나 | 어떻게 알았나 |
|---|---|---|
| 수집 초기 | **채널당 상한 10** | 월별 집계가 매달 10건 근처 |
| 08.23 | **추출 방법** (정렬 없는 페이징) | **현준님이 재현 안 된다고 알려주심** |
| 08.24 | **소스 비율** (색인 92%가 짧은 댓글) | 소스별로 나눠 물어보니 드러남 |

셋 다 **오류가 안 나고 결과가 그럴듯하게 나왔습니다.**

특히 두 번째는 제가 "커머스 랭킹에 완전 중복 37%" 라고 잘못 보고한 건입니다.
**서버가 아니라 제 추출 문제**였고, 정정했습니다. 그때 제가 지운 게 중복이 아니라
**결과 하나**였습니다 — 올리브영 100위권은 실제로 6일에 38계단 움직이고, 프로모션이
랭킹을 미는 구조입니다.

**그래서 자기 검사를 코드에 박았습니다.**

```
행수 대조        서버 count=exact 와 안 맞으면 중단
재현성 검사      커밋된 338행이 지금 코드로 재생성되는지
계약 검증기      청크 위반 11종
기저율 병기      적중률만 내는 검증은 검증이 아니라 홍보
--demo           거의 모든 스크립트가 데이터 없이 로직 점검
```

문서에 적어 두는 것보다 낫습니다.

## 6. 여쭙고 싶은 것

| # | 누구 | 무엇 |
|---|---|---|
| 1 | 석현님 | **LLM 이 지금 무엇을 근거로 답합니까?** 집계 숫자만이면 저희 색인이 근거 도구로 들어갈 자리가 있습니다. 이미 원문을 인용하면 불필요합니다 |
| 2 | 현준님 | **PostgREST 노출 스키마에 `academic` 추가** — 논문을 저희 쪽에 붙이는 유일한 경로입니다 |
| 3 | 현준님·석현님 | **LLM 앱이 두 개입니다.** 같은 질문에 다른 숫자를 답하면 발표에서 문제가 됩니다. 어느 DB 를 보는지 맞춰야 합니다 |
| 4 | 석현님 | daisomall 카테고리 세분화 / `rank_delta` 계산 방식 |
| 5 | 수호님 | 청크 생성기 `doc_id` 분리 + 길이 상한 700 → **500** (합의됨) |

**3번이 가장 급합니다.** 현준님 앱이 보던 행 수가 서버의 절반이었습니다
(80,102 vs 173,007). 두 앱이 각자 다른 사본을 보고 있으면 데모 중에 숫자가 갈립니다.

**2번이 풀리면** 성분별 3소스 대조표가 완성됩니다.

```
성분              논문 수    처방 채택률          담론 언급
나이아신아마이드   ← 이것만   375제품 · 중앙 9위    영상 33 · 댓글 257
아데노신          ← 이것만   374제품 · 중앙 33위   ...
```

**세 축이 어긋나는 성분이 R&D 공백**입니다. 논문은 많은데 처방 채택이 낮고 담론도
없는 성분 — 예측이 아니라 현재 상태의 비대칭이라 후향 검증에서 살아남는 종류입니다.
