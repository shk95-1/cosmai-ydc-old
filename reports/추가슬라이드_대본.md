### 1장 · 데이터 인제션 — 버리지 않고 표시한다 (30초)

> 수집과 정제를 제가 맡았습니다. **원칙은 하나입니다 — 지우지 않고 표시합니다.**
>
> 빈 텍스트, 중복 댓글, 광고 영상, 부분 수집. 이걸 다 플래그로만 남깁니다.
> 지우면 나중에 **「빼면 결론이 어떻게 달라지나」를 물을 수 없기** 때문입니다.
> 앞에서 말씀드린 광고 19칸이 그 질문의 답입니다.
>
> 수집은 전수로 받고 원본 JSONL 을 그대로 둔 다음 그 옆에 정규화 CSV 를 만듭니다.
> **매니페스트에 호출 수와 쿼터, 한계를 기록**해 둡니다.
>
> 정제에서 봐 주실 건 **정규화 함수를 하나만 쓴다**는 겁니다. 엔티티 → NFKC →
> 제어문자 → 공백 축약. 소스마다 정규화가 다르면 소스 간 비교가 무의미해집니다.

### 2장 · 공통 스키마 5계층 (25초)

> 레포는 사람 수만큼 네 개인데 **붙는 곳은 한 군데입니다 — document 테이블**입니다.
>
> 받은 그대로가 raw_record, 정규화 본문이 document 26만 행, 주제·성분 언급이
> mention 10만 행, 성분 표준화가 entity_link, 그 위가 구성비 지표입니다.
> **document 아래는 소스별이고 그 위는 공통입니다.**
>
> 운영은 컨테이너를 스케줄 단위로 잡아서 **한 소스가 죽어도 나머지가 돕니다.**
>
> 오른쪽이 계약입니다. **운영 DB 에 대한 상시 승인은 「추가만」입니다** —
> DROP 이나 타입 변경은 정규식으로 거부합니다. 그리고 테스트도 진짜 Postgres 를
> 띄웁니다. 「프로덕션은 Postgres, 테스트는 SQLite」가 방언 버그를 내보내기 때문입니다.

*[질문이 깊게 오면] OpenSSL 3.5 이상이 필요한 이유만 답하세요 —
bookworm 의 TLS 스택이 oliveyoung 리뷰 API 의 Cloudflare 챌린지에 막혀서
A/B 로 실측하고 테스트로 하한을 못박았습니다.*

### 3장 · 리뷰 감성 분석 — LLM 은 한 지점에만 (35초)

> 감성 분석도 제가 맡았습니다. **규칙이 기본이고 LLM 이 예외입니다.**
>
> 먼저 사전과 패턴 기반 규칙으로 극성을 판정합니다. 설치도 의존성도 없고
> 결과가 결정적이라 재현됩니다. 비용은 0입니다.
>
> 그 다음이 게이트입니다. **400문장 평가셋을 규칙이 넘으면 거기서 끝냅니다.**
> 못 넘는 구간만 LLM 으로 넘깁니다.
>
> LLM 은 claude-sonnet-5 를 structured output 으로 부르고 Batches API 로 묶습니다.
> **$10 하드스톱을 호출 전에 예약하고 실측으로 덮어씁니다.**
>
> 왜 이렇게 나눴는지 아래 세 줄입니다. **재현성** — LLM 출력은 같은 입력에도
> 흔들립니다. **비용 상한** — 예산을 다 쓰면 멈추고 어디까지 했는지 남깁니다.
> **교체 가능성** — 같은 프롬프트를 로컬 모델로도 왕복시켜 비교합니다.
>
> 네 레포 전체에서 LLM 이 있는 곳은 두 군데뿐입니다.

### 4장 · 규칙에서 LLM 으로 바꿀지 무엇을 보고 판정했나 (30초)

> **「LLM 이 더 잘한다」는 느낌으로 바꾸지 않았습니다.**
>
> 400문장을 고정하고, 규칙 출력을 **바이트 단위로 저장**합니다. 같은 400문장을
> LLM 으로 판정해서 두 출력을 대조합니다. **사람이 눈으로 보지 않습니다.**
> LLM 이 이긴 구간만 넘깁니다.
>
> 오른쪽이 LLM 에 넘기지 않은 것입니다. **숫자, SQL 생성, 집계, 쓰기.**
> 시스템 프롬프트 첫 줄이 「숫자를 직접 만들지 마라」입니다.
> 숫자는 Postgres 가 만들고 LLM 은 어느 도구를 부를지만 정합니다.
>
> 아래가 한계입니다. **평가셋이 400문장이라 정확도를 주장하지 않고
> 「규칙보다 나은 구간이 있다」까지만 말합니다.** 리뷰는 구매자만 쓰니
> 안 산 사람의 극성은 없고, 제품 바스켓이 바뀌면 수준이 바뀝니다.
>
> **그래서 극성은 판정에 직접 쓰지 않고 근거로만 씁니다.** 카드의 주장은
> 구성비에서 나오고 극성은 그 옆에 붙습니다.
