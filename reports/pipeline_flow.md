# 전체 흐름 — 수집에서 검색까지 무엇을 어떻게 했나

> 2026.08.24 · 김시현 (유튜브·시계열 파트)
> 이 문서는 "무엇을 만들었나"가 아니라 **"데이터가 어떤 손을 거쳐 결론이 됐나"** 를 순서대로 적은 것입니다.

## 0. 한 장으로 본 흐름

**소스마다 ①②가 다르고 ③부터 같습니다.** 정제는 그 소스를 아는 사람만 할 수 있고, 공통 스키마부터는 같은 코드가 처리합니다.

**관통하는 원칙 하나.** 각 단계에서 **버리지 않고 표시**합니다. 빈 텍스트·중복 댓글·광고 영상·부분 수집을 지우지 않고 플래그로 남깁니다. 그래야 "빼면 결론이 어떻게 달라지나"를 나중에 물을 수 있습니다.

## 1. 수집 — 무엇을 어떻게 받았나

`youtube_collector.py`

| | |
|---|---|
| 경로 | YouTube Data API v3 (`channels.list` + `playlistItems.list`) |
| 왜 `search.list` 를 안 썼나 | 쿼터가 100배 비싸고 결과가 재현되지 않습니다 |
| 모집단 | 시드 채널 **43개** (고정 패널), 2023-07-01 이후 |
| 받은 것 | 영상 13,979편 + 그 영상의 댓글 |
| 저장 | 원본 JSONL 을 그대로 남기고, 그 옆에 정규화 CSV |

**원본을 지우지 않는 게 중요합니다.** 기획안 §4 — *"원천·수집 시각·변환 이력이 보존되지 않으면 결과를 재현하거나 검증할 수 없다."* 나중에 "태그를 넣으면 어떻게 되나"를 물을 수 있었던 것도 원본에 태그가 남아 있었기 때문입니다.

### 여기서 한 번 크게 틀렸습니다

처음 수집은 **채널당 상한 10편**이었습니다. 그 데이터로 월별 집계를 냈더니 매달 10건 근처가 나왔고, 그게 트렌드처럼 보였습니다. **상한이 곧 관측값이 된 것**입니다. 재수집했습니다.

이 경험이 뒤에서 두 번 더 쓰였습니다 — 커머스 랭킹의 관측 깊이 문제(§7), 그리고 팀원의 "수집기 고장과 시장 침체는 똑같이 0건" 지적이 같은 종류입니다.

## 2. 정제 — 무엇을 고치고 무엇을 표시만 했나

### 정규화는 한 함수만 씁니다

`trend.normalize_text` 하나입니다.

```
HTML 엔티티 해제  →  유니코드 NFKC  →  제어문자 제거  →  공백 축약
```

**소스마다 정규화가 다르면 소스 간 비교가 무의미해집니다.** 그래서 커머스·성분표·논문이 붙어도 이 함수를 씁니다. 실측으로 이 정규화가 주제 매칭 결과를 바꾼 경우는 영상 5,957편 중 3편(0.05%)뿐이었습니다. 그런데도 적용하는 이유는 두 가지입니다.

1. **중복 댓글 판정의 기준이 필요합니다.** 정규화 없이 비교하면 공백만 다른 복붙이 서로 다른 댓글로 남습니다(실측 2,395건 = 1.1%)
2. NAVER 블로그처럼 HTML 이 그대로 오는 소스에 같은 계약이 필요합니다

### 지운 것과 표시한 것

| 대상 | 처리 | 왜 |
|---|---|---|
| 빈 텍스트 | **표시** (`quality_flags=empty_text`) | 행을 지우면 분모가 흔들립니다 |
| 같은 영상 안 동일 댓글 | **표시** (`duplicate_in_parent`) | 복붙 스팸이 언급량을 부풀립니다 |
| 다른 영상의 같은 댓글 | **그대로 둠** | 각각 실제 반응입니다 |
| 쇼츠(60초 이하) | **분리** | 아래 참조 |
| 광고·협찬 | **표시만** | §7 에서 빼고 다시 계산해 비교 |
| 태그 | **본문에서 제외, 메타에 보존** | 아래 참조 |

### 쇼츠를 분리한 이유 — 숫자로

| | 쇼츠 | 장문 |
|---|---:|---:|
| 설명란 길이 중앙 | 0자 | 709자 |
| 주제 매칭률 | 13.1% | 64% |
| 분기별 비중 | **55% → 41% 로 움직임** | |

쇼츠와 장문을 한 분모에 넣으면 **포맷 선택의 변화가 주제 트렌드로 위장됩니다.** 그래서 분모는 장문만입니다.

### 태그를 뺀 이유

기획안 문장은 "제목+설명+태그"였는데 계산은 제목+설명만 씁니다. 태그를 넣으면 모집단이 **964 → 1,019편**이 되고 모든 구성비가 움직입니다. 그리고 태그로만 걸린 57편을 열어보니 올영하울·핸드크림·브이로그였습니다 — SEO 용 태그라 내용을 나타내지 않습니다.

태그는 `source_metadata.tags` 에 보존돼 있어 재수집 없이 결정을 바꿀 수 있습니다.

### 성분표 정제 (`normalize_ingredients.py`)

수호님이 식약처 × 올리브영을 매핑해 주신 CSV 입니다. 원본 30,097행 / 577제품.

| 문제 | 처리 |
|---|---|
| 성분명 공백 손상 (`에칠헥 실트리아존`) | 공백 제거로 병합 — **445건** |
| 전성분이 한 덩어리로 뭉침 | 사전 대조로 분해 — 28건 중 6건 성공, 248행 증가 |
| 해독률 미달 | **원본 유지 + "집계에서 제외할 것" 표시** — 22행 |

**해독 못 한 것을 억지로 쪼개지 않았습니다.** 잘못 쪼갠 성분명은 조용히 틀린 집계를 만듭니다. 대신 그 22행 때문에 **제품 21개가 통째로 빠집니다**(키엘·라로슈포제·랑콤 등 수입 브랜드). 이건 손실로 기록했습니다.

### 커머스 랭킹 정제 (`commerce_ranking.py`)

석현님 수집기가 PostgREST 서버에 쌓는 `rank_snapshot` 입니다. 08.24 기준 171,030행,
네 소스(oliveyoung · glowpick · daisomall · hwahae) 6일치 · 시간당 스냅샷입니다.

**그대로 쓸 수 없었습니다.** 두 가지를 걷어내야 했습니다.

| 문제 | 규모 | 처리 |
|---|---|---|
| 완전 중복 행 | **62,812행 (37%)** | `(소스·보드·카테고리·시각·순위·제품)` 으로 제거 |
| 스냅샷 관측 깊이가 다름 | 1,298개 중 90개(7%) 불완전 | 상위 N위까지 관측한 스냅샷만, 그 안에서 N위 이내만 |

중복은 `product_name`·`price` 까지 같은 완전 중복이고, **네 소스가 정확히 37%씩**이라
특정 수집기가 아니라 공통 적재 경로 문제입니다. 그리고 **08.18~19 에는 0건이고
08.20 부터 날마다 커집니다**(08-20 129 → 08-23 287 스냅샷, 최대 5배).

깊이 문제는 우리가 유튜브에서 겪은 **수집 상한 아티팩트와 같은 종류**입니다.
`oliveyoung suncare` 가 관측한 최하위 순위가 스냅샷마다 22위~100위로 달랐습니다.
얕은 스냅샷에 없는 제품을 그대로 읽으면 "이탈"이나 "급락"이 됩니다.

**보정이 결론을 바꿨습니다.**

| oliveyoung 선케어 | 보정 없음 | 상위 20위 보정 후 |
|---|---:|---:|
| 중앙 변동폭 | 33계단 | **8계단** |
| 신규 진입 | 121건 | **8건** |
| 이탈 | 1건 | **10건** |

보정 없는 상위 목록이 전부 `96→28`, `84→24` 처럼 90위권에서 30위권으로 뛰는
것들이었습니다. 실제 상승이 아니라 **얕은 스냅샷에서 안 보이던 제품이 깊은
스냅샷에서 나타난 것**입니다. 보정하면 `19→1`(VT), `17→2`(스킨1004) 처럼
상위권 안의 실제 이동이 남습니다.

**보정 전/후를 둘 다 냅니다** (`commerce_ranking_raw.csv` / `commerce_ranking.csv`).
하나만 내면 아티팩트가 얼마나 컸는지 안 보입니다.

한계도 기록했습니다 — **daisomall·hwahae 는 선케어 분류가 없습니다**(daisomall 은
`category_name` 이 `뷰티/위생` 하나뿐). 지금 선케어 시계열은 oliveyoung 6,480행 +
glowpick 1,082행 둘로만 됩니다.

## 3. 공통 스키마 — 소스를 붙일 수 있게 만드는 지점

`to_common_schema.py`

5계층입니다. 팀 합의 사항입니다.

```
raw_record          원본 그대로
document            문서 하나 = 한 행   ← 여기가 결합 지점
mention             (문서, 주제) 쌍
entity_link         문서 ↔ 제품 연결   (PoC 에서 미완)
topic_daily_metric  집계
```

`document` 의 칸은 이렇습니다.

```
doc_id · source · source_item_id · content_type · parent_item_id ·
channel_id · published_at · url · text · quality_flags · source_metadata
```

**`source` 를 하드코딩하지 않는 것이 핵심입니다.** 그래서 커머스·논문·NAVER 가 같은 스키마로 변환되면 **행이 늘어나는 것뿐이고 뒤의 코드가 안 바뀝니다.** 실제로 BM25·청크 생성기·평가기 모두 `source` 를 읽어서 씁니다.

현재 유튜브 변환 결과입니다.

| | |
|---|---:|
| document | 261,317행 |
| mention | 105,358행 |
| channel | 43행 |

검증 삼종(재현 시 반드시 같아야 하는 값): **선크림 장문 964편 / 댓글 60,348건 / 중복 제외 60,311건**

## 4. 지표 — 트렌드를 무엇으로 봤나

`trend.py`

### 빈도를 직접 쓰지 않습니다

이게 이 파트의 가장 중요한 결정입니다. 유튜버 설명란 길이 중앙값이 3년간 **1,253자 → 709자(−44%)** 로 줄었습니다.

| | 문서 기준 비율 | **구성비** |
|---|---:|---:|
| 13주제 변화량 합계 | **−28.6%p** | −0.0%p (정의상 0) |
| 하락한 주제 수 | **10 / 13** | 6 / 13 |

문서 기준으로 보면 **13개 주제 중 10개가 "사라짐"** 이 됩니다. 트렌드가 아니라 유튜버들이 설명을 짧게 쓰기 시작한 것입니다.

```
구성비 = 그 주제 언급 문서 수 ÷ 그 기간 전체 주제 언급 문서 수
```

분자와 분모가 같이 줄어 드리프트가 상쇄됩니다.

### 비교는 전년 동분기(YoY)

선크림은 계절 상품입니다. 장문 중 선크림 언급 비중이 **3년 연속 Q2 최고**(26.7 / 25.3 / 25.6%)입니다. 인접 분기를 비교하면 매년 Q2 에 급상승, Q4 에 사라짐이 나옵니다.

### 영상과 댓글을 합치지 않습니다

둘이 다른 것을 측정합니다.

| 주제 | 영상 설명 | 댓글 |
|---|---|---|
| SPF | 11/13분기 | 9/13 |
| **백탁** | **0/13분기** | **12/13** |

가중합으로 섞으면 **"소비자는 불만을 말하는데 제작자는 안 다루는 주제"** 라는 신호가 사라집니다. 그래서 나란히 두고, 그 차이를 `gap`(댓글 − 영상)으로 씁니다. **`gap` 이 제품 공백 신호입니다.**

### 나머지 지표

| 지표 | 정의 |
|---|---|
| `persistence` | 최근 4분기 중 구성비가 그 주제의 전체 기간 중앙값을 넘는 분기 수 |
| `channel_diffusion` | 고유 채널 수 50% + 채널 분포 엔트로피 50% |
| `evidence_strength` | 유효 근거 수 43.75% + 고유 채널 수 31.25% + 비중복 비율 25% |

`channel_diffusion` 에 엔트로피를 넣은 이유는 비율만 보면 "3채널이 골고루"와 "1채널이 몰아서"를 구분하지 못하기 때문입니다.

## 5. 판정 — 임계값을 어떻게 정했나

`judge.py`

```
근거 부족   evidence_strength < 50  또는  document_count < 5
신규 등장   직전 3분기 구성비 < 1%  &&  현 분기 문서 ≥ 5  &&  채널 2개 이상
단기 피크   velocity > +τ  &&  persistence = 1
급상승      velocity > +τ  &&  persistence ≥ 2
채널 확산   channel_diffusion 전년 동분기 대비 +0.089 초과  &&  velocity ≤ +τ
지속 인기   |velocity| ≤ τ  &&  persistence ≥ 3
사라짐      velocity < −τ  &&  현 분기 구성비 < 최고 분기의 절반
```

**임계값을 실측 분포에서 뽑았습니다.**

| 임계값 | 값 | 어떻게 |
|---|---|---|
| `τ` | **0.35** | 실측 YoY 분포 75분위. 영상 0.366 · 댓글 0.358 로 두 소스가 독립 계산인데 거의 일치 |
| `DIFFUSION_TAU` | **0.089** | 같은 방법 — 전년 동분기 변화량 234셀의 절대값 75분위 |

**한 번 뽑아 고정하고 분기마다 재계산하지 않습니다.** 재계산하면 아무 변화 없는 분기에도 상위 25%가 급상승으로 찍힙니다. 그리고 **소스마다 다시 뽑아야 합니다** — 지금 값은 유튜브 실측치입니다.

### 채널 확산 임계값은 한 번 조였습니다

처음엔 "0보다 크면 상승"이었습니다. 그랬더니 판정된 89셀 중 **52셀(58%)** 이 채널 확산으로 쏠렸습니다. 유형이 한 곳에 몰리면 분류의 정보량이 없습니다. 실측 75분위로 조이니 52 → 14셀이 되고, 남은 것은 +0.10 ~ +0.54 의 실제 도약이었습니다.

### 결과 (338행 = 13주제 × 13분기 × 2소스)

| 우리 | 시도하지 않음 |

원인도 확인됐습니다 — 올리브영 상품의 상당수가 `기획/N종 택1` **묶음 페이지**입니다. 제품 하나가 아니라 진열대입니다. 성분표에서도 성분 100개 넘는 제품이 21개(최대 385행)였습니다.

**조인율을 억지로 올리면 틀린 성분–반응 연결이 분석 전체를 오염시킵니다.** 낮은 조인율을 인정하고 각 소스를 독립 축으로 씁니다.

여기가 이 파트에서 가장 공들인 부분입니다. **판정기와 채점기를 따로 만들었습니다.**

### 광고 — 빼도 안 빼도 손실입니다

선크림 장문 964편 중 **465편(48.2%)이 광고·협찬**입니다. 신고 필드(`has_paid_product_placement`)는 254편뿐이고 설명란 문구로 407편이 걸립니다 — **신고만 믿으면 절반을 놓칩니다.**

빼면 판정 64셀 중 **19셀 뒤집히고 24셀이 표본 미달로 사라집니다.** 그래서 빼지 않고 **필터 민감으로 표시**합니다. 464편을 버리면 13주제 중 절반이 판정 불가가 되어 도구가 아무 말도 못 합니다.

### 재현성 검사가 버그를 잡았습니다

같은 run 디렉터리를 실수로 두 번 넘기면 `raw` 카운트만 두 배가 되어 `unique_ratio` 가 절반으로 떨어졌습니다. 문서 수는 안 늘어나는데 비중복 비율만 망가지는 — **조용히 틀리는 종류**입니다. 댓글을 `comment_id` 로 한 번만 세도록 고쳤습니다.

그리고 **정본 run 이 확정됐습니다.** `data/panel` 두 개입니다.

### 오류 주입 — 429 와 403 의 구분

기획안이 지정한 것을 그대로 주입했습니다. 가장 중요한 건 **429(rate limit)와 403(quotaExceeded)의 구분**입니다. 429 는 기다렸다 다시 걸어야 하지만 403 은 하루가 지나야 풀립니다. 둘을 같이 다루면 남은 쿼터를 태우며 3번 더 부릅니다. 코드에 그 구분이 실제로 있었습니다.

### 후향 검증 — 가장 불편한 결과

과거 분기까지만 알고 있었던 것처럼 지표를 다시 계산해 판정하고, 그 뒤 4분기를 봤습니다. `persistence` 의 기준선이 전체 기간 중앙값이라 자르지 않으면 **미래를 보고 판정**하게 됩니다. 그래서 `CUTOFF_QUARTER` 훅을 넣었습니다.

| 기준 | 질문 | 적중 | 기저율 |
|---|---|---:|---:|
| A | 판정 후에도 계속 올랐나 | **27%** | 47% |
| B | 올라간 수준이 유지됐나 | **64%** | 47% |
| A (상승 계열 9건) | | **22%** | 47% |

**우리 지표는 서술 도구이고 예측 도구가 아닙니다.** 13분기 · 계절 상품 · 964편으로는 예측 모델을 세울 수 없습니다. 기획안도 *"표본이 충분할 때만 후행 지표 예측을 시도하고, 부족하면 통계 baseline 으로 대체"* 라고 적어 뒀고, 부족한 쪽이 맞았습니다.

**기저율을 같이 낸 것이 중요합니다.** 적중률만 내는 후향 검증은 검증이 아니라 홍보입니다.

> 팀의 ML 파트도 독립적으로 같은 곳에 도달했습니다 — 모델 A 가 persistence baseline 상대로 9판 6승 3패, 모델 E(논문 수 → 매출)는 넣으니 오히려 나빠졌습니다.

## 8. 청크 — 임베딩에 넣을 단위를 만드는 곳

### 나누는 지점을 여기로 정했습니다

인코딩(벡터 만들기)은 **한 사람이 전체를 한 번에** 돌립니다. 이유가 있습니다.

- **TF-IDF/SVD 는 애초에 나눌 수 없습니다.** 코퍼스에 학습되는 방식이라 두 사람이 각자 fit 하면 코드가 똑같아도 서로 다른 좌표계가 나옵니다
- 사전학습 모델은 나눌 수 있지만, 모델 리비전·프리픽스·L2 정규화·dtype·텍스트 정규화·입력 필드 **여섯 개가 전부 같아야** 합니다. 하나만 어긋나면 **오류 없이** 엉뚱한 결과가 나옵니다
- 전체 28만 청크를 GPU 로 돌리면 10~30분입니다. **나눠서 얻을 시간이 없습니다**

대신 **"뭘 한 덩어리로 볼지"는 그 소스를 아는 사람만 정할 수 있으므로** 소스별로 나눕니다.

### 계약은 다섯 칸입니다

```
chunk_id · doc_id · source · ordinal · text
```

`doc_id` 가 공통 스키마의 그것이라 **합치기가 join 이 아니라 이어 붙이기**가 됩니다. 합칠 게 없으니 못 합칠 일도 없습니다.

### 소스별 규칙

| 소스 | 한 청크 | 결과 |
|---|---|---|
| 유튜브 댓글 | 1건 = 1청크 (중앙 48자) | 252,332 |
| 유튜브 영상 | 제목+설명, 500자에서 분할 | 26,584 |
| 성분 — 제품 단위 | 브랜드 + 제품명 + 전성분 | 1,018 |
| 성분 — 성분 단위 | 성분 + 기능 + 채택률 + 함께 쓰이는 성분 | 2,265 |

**500자 근거**: `multilingual-e5-base` 상한이 512토큰이고 한국어는 대략 1.5자가 토큰 하나입니다. 500자면 약 330토큰이라 여유가 있습니다. 상한을 꽉 채우면 모델을 바꿀 때 다시 쪼개야 합니다.

**겹침(overlap)은 두지 않았습니다.** 겹치면 같은 문장이 여러 청크에 들어가 검색 상위가 한 문서로 채워집니다. 우리는 근거를 **여러 문서에서** 모아야 하므로 중복이 더 해롭습니다.

### 검증기를 같이 만들었습니다

```bash
python chunks.py --validate reports/chunks_상대.csv
```

28만 문서를 GPU 로 태운 다음 `doc_id` 가 어긋난 걸 알면 처음부터 다시입니다. 그래서 **인코딩 전에** 걸러야 합니다. 위반 11종을 잡는지 자체 점검에 넣었습니다 — 통과만 하는 검증기는 장식입니다.

### 성분 청크는 별도 파일이 필요했습니다

유튜브는 공통 스키마에 `doc_id` 가 있지만 **성분표에는 없습니다.** 그래서 `chunks.py` 를 성분표에 그냥 돌릴 방법이 없습니다(돌리면 유튜브가 나옵니다 — 실제로 그런 일이 있었습니다).

`ingredient_chunks.py` 가 `doc_id` 규칙을 정합니다.

```
ingredient_product:{제품명 sha1 앞 12자}
ingredient_term:{성분명}
```

그리고 **묶음 페이지를 걸렀습니다.** 고유 성분 80개 초과는 여러 SKU 가 섞인 페이지로 보고 채택 통계에서 뺍니다.

교차 확인: 나이아신아마이드 채택률이 **69.4%(540개 중 375개)** 로 나왔고, 석현님 MASTER_REPORT 의 **68.3%**(577 분모)와 사실상 일치합니다.

## 9. 검색 — 어휘 검색을 먼저 만든 이유

`bm25.py` · `retrieval_eval.py`

### 벡터보다 이걸 먼저 만들었습니다

임베딩 모델을 뭘로 정하든 **어휘 검색 기준선은 안 바뀝니다.** 기준선 없이 하이브리드를 만들면 "합친 게 더 낫다"를 확인할 방법이 없습니다. 후향 검증에서 기저율을 같이 낸 것과 같은 이유입니다.

### 둘이 반대로 약합니다

```
질의: "에칠헥실트리아존"
  BM25 → 그 문자열이 있는 문서를 정확히 찾는다
  벡터 → "화학 성분 이름 같은 것"이랑 다 비슷하다고 본다
         (에칠헥실메톡시신나메이트도 비슷하다고 나옴 — 성분이 다른데)

질의: "하얗게 떠서 싫다"
  BM25 → 못 찾는다. "백탁"이라는 글자가 없다
  벡터 → 찾는다. 뜻이 가깝다
```

실측입니다. 26만 문서 색인, `"하얗게 떠서 싫다"` 상위 5건 — **다섯 건 모두 백탁 얘기이고 다섯 건 모두 "백탁"이라는 단어가 없습니다.**

### 평가기 — 정답이 공짜로 있습니다

`common/mention.csv` 가 (문서, 주제) **105,358쌍**입니다. `match_topics()` 가 만든 것이라 사람이 라벨을 달 필요가 없습니다.

| 모드 | 질의 | 정답 | 목적 |
|---|---|---|---|
| `literal` | 별칭 하나 | 그 주제 문서 전부 | **고장 감지** |
| `heldout` | 별칭 A | A 의 토큰이 없는 같은 주제 문서 | **벡터가 넘어야 하는 바닥선** |

| 모드 | P@10 | MRR@10 | Hit@10 |
|---|---:|---:|---:|
| `literal` (고침 전) | 0.754 | 0.799 | 87% |
| `literal` (고침 후) | **0.862** | **0.907** | **93%** |
| `heldout` | **0.000** | 0.000 | 0% |

**`heldout` 0.000 은 측정이 아니라 정의입니다.** 정답을 "질의 토큰이 없는 문서"로 잡았으니 토큰이 겹치는 문서만 점수를 매기는 어휘 검색은 구조적으로 0 입니다. 발견이 아니라 **바닥선**이고, 벡터가 0 을 넘기면 그게 임베딩이 기여한 몫입니다.

### 평가기가 고장 셋을 잡았습니다

`literal` 을 고장 감지용으로 만들었는데 실제로 잡았습니다. **셋 다 에러가 안 나고 결과만 조용히 빕니다.**

근본 원인은 하나입니다 — **`topics.py` 는 부분문자열로 매칭하고 색인은 형태소로 나눕니다.**

```
신제품   → ['제품']        신 이 접두사로 떨어진다
화학적   → ['화학']        적 이 접미사로 떨어진다
차단지수 → ['차단','지수']  둘로 갈린다
제형     → []             제(접두) + 형(한 글자) 로 전멸한다
```

`제형` 이 빈 결과인 건 평가 문제가 아니라 **검색 결함**입니다. 그리고 고치는 과정에서 반대 방향 함정도 나왔습니다 — 별칭을 전부 명사로 등록하니 `하얗게`·`하얘` 가 서로 다른 토큰이 됐습니다(전에는 둘 다 `하얗`). **활용형을 명사로 박으면 형태소 통합이 깨집니다.** 그래서 등록 대상을 Kiwi 에게 물어서 고릅니다.

부수적으로 `add_user_word` 에 score 를 안 주면 **등록해도 조용히 무시된다**는 것도 확인했습니다.

## 10. 산출 — 무엇을 보여주나

### 드릴다운 화면 (`dashboard.py`)

강사님 요구가 *"결과를 누르면 근거가 쫙 나오는 형식"* 이었습니다.

```
격자(13주제 × 13분기 × 소스 탭)  →  셀 클릭
  →  판정 · 지표 8개 · gap · hold_reason
  →  그 분기 근거 댓글 원문 8건 (좋아요 상위) · 걸린 표현 · 원본 영상 링크
```

검증 절 8개가 아래에 붙습니다 — 소스 간 구성비, 자막 이득, 커머스 설문, 성분 축, **광고 민감도, 후향 검증, 사전 밖 성분, 커머스 순위 변동**.

### R&D 카드 3건 (`cards.py`)

| 카드 | 유형 | 근거 |
|---|---|---|
| 발림성 | 검증된 성장 | 기회 점수 67.9 |
| 혼합자차 | **표현 공백** | 제품 32.9% vs 담론 1.21% = **27.1배** |
| 자극_눈시림 | **제품 공백 기회** | gap **+5.29%p** (댓글 > 영상) |

**후향 검증 결과가 카드 유형 선택에 영향을 줍니다.** 혼합자차·자극_눈시림은 시점 비대칭이라 시간 주장이 없습니다. 발림성만 `opportunity_score` 에 velocity 가 0.35 들어가므로, **카드 문구에 "다음 분기에도 오른다"는 뜻이 들어가면 안 됩니다.**
