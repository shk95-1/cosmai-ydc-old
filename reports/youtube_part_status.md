## 2. 바로 쓸 수 있는 것 — LLM 도구로 붙이십시오

### ① 소스별 근거 검색

```bash
C:/Users/Admin/miniconda3/python.exe -X utf8 bm25.py \
  --query "판테놀 쓰는 선크림" --per-source --top 2
```

한 질의가 **여섯 소스에서 각각** 근거를 가져옵니다.

```
[youtube_comment]  판테놀 무기자차 선크림 진리임..ᅲ
[youtube_video]    무너진 피부장벽 판테놀을 써야하는 이유
[formula_full]     제로이드 데일리 선크림 — 전성분 26.판테놀, 27.펜틸렌글라이콜
[mfds]             앤서나인틴시카판테놀데일리선크림 · 바이오톡스 · 2019-04-15 · SPF50+ PA++++
[ingredient]       판테놀 — 209개 제품 36.2% · 평균 배합순위 28위로 미량 배합
[formula_summary]  듀이트리 어반쉐이드 더마 판테놀5 — 무기자차 · 전성분 36종
```

**전역 상위 k 를 쓰면 안 됩니다.** 색인의 92%가 짧은 유튜브 댓글이라 BM25 의 길이
보정이 그쪽을 독점합니다. `mfds` 는 전역 293위, `ingredient` 는 300위 밖이었습니다.
**소스별로 나눠 물어야** 근거가 모입니다.

각 결과에 `doc_id` · 소스 · 원본 링크가 붙습니다. **LLM 이 숫자를 답할 때 그 숫자의
원문 근거를 대는 자리입니다.**

### ② 의미 검색 (이름 없는 표현)

`"하얗게 떠서 싫다"` 상위 5건이 전부 백탁 얘기인데 **전부 "백탁"이라는 단어가
없습니다.** ILIKE 나 어휘 검색이 구조적으로 못 하는 일입니다.

현준님 `search_reviews` 의 ILIKE 약점("보습"으로 "촉촉"을 못 찾음)을 이게 메웁니다.

### ③ 청크 계약 검증기

```bash
python chunks.py --validate 받은파일.csv
```

계약 5칸(`chunk_id · doc_id · source · ordinal · text`) 위반 11종을 잡습니다.
**인코딩 전에 걸러야 합니다** — 30만 청크를 GPU 로 태운 다음 `doc_id` 가 어긋난 걸
알면 처음부터 다시입니다.

### ④ 성분 사전

`seeds/ingredient_dictionary.tsv` 1,877행 (수호님 것에서 각주·안내문 21항목 제거).

**효과를 측정했습니다.** 성분명이 한 토큰으로 나오는 비율이 **41% → 100%** 입니다.

```
사전 없이:  1,2-헥산다이올 → ['1', ',', '2', '-', '헥산다이올']
```

**성분명 절반 이상이 검색 불가였습니다.** 성분을 다루는 어느 코드든 이 사전이 필요합니다.

## 3. 검색기 셋을 같은 기준으로 재봤습니다

| 모드 | bm25 | vector | hybrid |
|---|---:|---:|---:|
| `literal` P@10 | **0.828** | 0.567 | 0.710 |
| `literal` Hit@10 | 93% | 89% | **98%** |
| `heldout` P@10 | **0.000** | **0.042** | 0.032 |
| `heldout` Hit@10 | 0% | **17%** | 13% |

`literal` = 주제 별칭으로 물어 그 주제 문서를 찾는 것 (고장 감지용).
`heldout` = 별칭 A 로 물어 **A 의 토큰이 하나도 없는** 같은 주제 문서를 찾는 것.

### 임베딩은 채택 — 기준을 미리 정해 뒀습니다

`heldout` 에서 BM25 는 **구조적으로** 0.000 입니다(정답을 "질의 토큰이 없는 문서"로
잡았으니). 그래서 기준이 **"0을 넘느냐"** 였습니다. 결과를 보고 기준을 만들면 그건
성능이 아닙니다.

벡터가 **0.042 · Hit 17%**. 60개 질의 중 10개에서 글자가 하나도 안 겹치는 문서를
찾았습니다. 점수 대부분이 `톤 업`(P@10 1.00)·`눈 시림`(0.60) 두 질의에서 나오는데,
둘 다 **공백이 든 별칭**입니다 — BM25 는 조각나서 0점입니다.

### 하이브리드(RRF)는 쓰지 않습니다

양쪽에서 중간입니다 — 어휘 0.828 → 0.710, 의미 0.042 → 0.032. **서로를
끌어내렸습니다.** RRF 가 순위만 보고 확신도를 무시하기 때문입니다.

**대신 용도별로 갈라 씁니다.**

```
성분명 · SPF · 브랜드 (정확 일치가 정답)   →  BM25
"하얗게 떠서 싫다" (이름 없는 표현)         →  벡터
```

근거는 합치는 게 아니라 나란히 놓습니다 — 소스를 합산하지 않은 것과 같은 논리입니다.

## 5. 저희가 못 하는 것 (발표 방어선)

### ① 예측이 안 됩니다

후향 검증 11건입니다. 과거 시점까지만 알고 있었던 것처럼 판정하고 그 뒤 4분기를 봤습니다.

| 기준 | 적중 | 기저율 |
|---|---:|---:|
| A 판정 후에도 계속 올랐나 | **27%** | 47% |
| B 올라간 수준이 유지됐나 | **64%** | 47% |
| A (상승 계열 9건만) | **22%** | 47% |

13분기 · 계절 상품 · 964편으로는 예측 모델을 세울 수 없습니다. **그래서 카드는
"뜰 것이다"가 아니라 "지금 이런 비대칭이 있다"로 씁니다.**

> 팀의 ML 파트도 독립적으로 같은 곳에 도달했습니다 — 모델 A 가 baseline 상대로
> 9판 6승 3패, 모델 E(논문 수 → 매출)는 넣으니 오히려 나빠졌습니다.

### ② 제품 단위 조인이 안 됩니다

팀에서 **세 사람이 독립적으로 같은 벽**에 부딪혔습니다.

```
팀원 매처          100개 중 38개
MASTER_REPORT     정확일치 119/577 (20.6%), 퍼지매칭은 오매칭으로 폐기
저희              시도하지 않음
```

원인도 같습니다 — 올리브영 상품의 상당수가 `기획/N종 택1` **묶음 페이지**입니다.
제품이 아니라 진열대입니다. 성분표에서도 고유 성분 80개 넘는 제품이 21개였습니다.

### ③ 사전에 없는 성분은 관측되지 않습니다

그 한계를 숫자로 재서 11종을 찾았고, **자동으로 사전에 넣지 않았습니다** — 넣으면
임계값·판정·카드가 전부 다시 계산되고 팀에 공유한 숫자와 어긋납니다.

## 6. 같은 함정을 다섯 번 밟았습니다

**다섯 번 다 오류가 안 나고 결과가 그럴듯했습니다.**

| 언제 | 무엇이 관측값이 됐나 | 어떻게 알았나 |
|---|---|---|
| 수집 초기 | **수집 상한 10** | 월별 집계가 매달 10건 근처 |
| 08.23 | **추출 방법** (정렬 없는 페이징) | **현준님이 재현 안 된다고 알려주심** |
| 08.24 | **소스 비율** (색인 92%가 짧은 댓글) | 소스별로 나눠 물어보니 드러남 |
| 08.24 | **id 형식** (정답 `doc_id` vs 결과 `chunk_id`) | 벡터가 0.000 이 나와서 의심 |
| 08.24 | **문서의 명령** (`python` 이 스토어 스텁) | 붙여 넣었더니 `Python ` 만 찍힘 |

두 번째는 제가 **"커머스 랭킹에 완전 중복 37%"** 라고 잘못 보고한 건입니다. 서버가
아니라 제 추출 문제였고 정정했습니다. **그때 제가 지운 게 중복이 아니라 결과
하나였습니다** — 올리브영 100위권은 실제로 6일에 38계단 움직이고, 프로모션이 랭킹을
미는 구조입니다.

네 번째가 가장 아까웠습니다. 그대로 봤으면 **"임베딩은 이득이 없다"고 잘못 결론
내리고 발표했을 겁니다.**

### 그래서 자기 검사를 코드에 박았습니다

| 장치 | 무엇을 막나 |
|---|---|
| 행수 대조 | 페이징 중 집합 변화 (서버 `count=exact` 와 안 맞으면 중단) |
| 재현성 검사 | 커밋 산출물이 지금 코드로 안 나오는 것 |
| 계약 검증기 | 청크 위반 11종 |
| 기저율 병기 | 적중률만 내는 자기 홍보 |
| 캐시 키에 설정 해시 | 설정을 바꿔도 옛 색인을 쓰는 것 |
| 채택 기준 사전 고정 | 결과를 보고 기준을 만드는 것 |
| `--demo` | 데이터 없이 로직이 죽은 것 |

문서에 적어 두는 것보다 낫습니다. **발표에서 저희 파트가 할 이야기가 이거라고 봅니다.**

**1번이 가장 급합니다.** 논문은 "없다"가 아니라 **"못 본다"** 입니다. 현준님 앱이
`academic.paper_trend` 를 직접 쓰고 있고, PostgREST 는 등록된 스키마만 노출하므로

풀리면 **성분별 3소스 대조표**가 완성됩니다.

```
성분              논문 수      처방 채택률 · 배합순위        담론 언급

아데노신           ← 이것만    374제품 69.3% · 중앙 33위    영상  ? · 댓글   ?
마데카소사이드       ← 이것만     72제품 13.3%              영상 50 · 댓글  58
```

**세 축이 어긋나는 성분이 R&D 공백입니다.** 논문은 많은데 처방 채택은 낮고 담론도
없는 성분 — 예측이 아니라 **현재 상태의 비대칭**이라 후향 검증에서 살아남는
종류입니다. 두 축은 지금 있고 논문 하나만 오면 됩니다.

**3번도 확인이 필요합니다.** 현준님 앱이 보던 행 수가 서버의 절반이었습니다
(80,102 vs 173,007). 두 앱이 각자 다른 사본을 보고 있으면 데모 중에 숫자가 갈립니다.
